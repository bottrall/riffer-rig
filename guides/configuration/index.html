Settings live in two files with the same name and shape, both optional:

  • ~/.riffer/settings.json — the home scope, for every project.
  • <cwd>/.riffer/settings.json — the project scope, for sessions started in that directory.

A file that is missing or blank counts as empty. A file that is not valid JSON, or does not hold a JSON object, is never read as empty and never written over: riffer stops before the session starts, naming the file and the line and column where parsing stopped, and leaves the file’s text out of the message.

Where each value comes from

The highest source that is set wins.

Value 1 2 3 4 5
Model --model a resumed session’s /model switch1 RIFFER_MODEL model in project, then home settings asked on first run, saved to home2
Reasoning level --reasoning a resumed session’s /reasoning switch RIFFER_REASONING reasoning in project, then home settings the model’s own default
Provider credential the provider’s environment variables auth.json (secrets) or the providers block (plain values) a provider fallback, such as the AWS shared config for the Bedrock region asked for, then stored (required fields only) —

Inside a session, /model and /reasoning override all of these until the session ends (below). Providers has the credential details.

Scopes and merging

The project file wins over the home file key by key. A few keys merge differently:

Key Read from When both scopes set it
most core keys both the project’s value wins
an extension namespace both merged one level down, so a project can change one key and keep the rest
extensions.disabled both the lists add up: a project can disable more, never re-enable
catalog_files both the lists add up, home files first; a later file wins a repeated model
mcp.servers both merged by server name; a project server replaces a home one whole
providers home only —

Core keys

Every core key is top level and optional. Every other top-level key is an extension namespace.

Key What it sets
model the model new sessions start with, as "provider/name" (below)
reasoning the reasoning effort (below)
catalog_files the model catalog files holding pricing and reasoning maps (below)
providers non-secret provider fields such as an endpoint or region (Providers)
extensions disabled and autoload (below)
reload "auto" (default) or "manual" (below)
sessions {"save": false} stops saving sessions (Sessions)
tools the provider-native tool switches (below)

model

{ "model": "anthropic/claude-sonnet-4-6" }

The provider’s identifier, a slash, then the provider’s own model name. The provider is one of anthropic, openai, gemini, openrouter, azure_openai or amazon_bedrock, or one an extension registers. Everything after the first slash goes to the provider unchanged, so openrouter/anthropic/claude-sonnet-4-6 works as written.

A name without a known provider prefix is rejected with the list of providers; riffer never guesses the provider from a bare name. A bare RIFFER_MODEL is rejected even when --model is also given.

/model provider/name switches the model for the current session, keeping the conversation. It sets up the new provider the way startup does — offering its SDK gem and asking for missing credentials — and leaves the model unchanged if that fails. /model alone shows the model in use.

/model --save writes the model in effect to the home settings.json, so new sessions start with it; /model provider/name --save switches and saves in one step. A switch that fails saves nothing.

reasoning

{ "model": "anthropic/claude-sonnet-4-6", "reasoning": "high" }

One of off, low, medium, high, xhigh or max. riffer translates the level into each provider’s own parameters, and a model’s entry in a catalog file can override that mapping. Leaving reasoning out keeps the model’s default.

Source A level riffer does not accept…
--reasoning, RIFFER_REASONING is rejected before the session starts, listing the accepted levels
settings.json is ignored, and the model’s default applies

Settings are lenient so that one level can stay in the file while you switch between providers.

/reasoning level switches the level for the current session and is restored when you resume it; /reasoning alone shows the level in effect (default when none is set). /reasoning --save and /reasoning level --save save to the home settings, as /model does. The level stays in effect across a /model switch. A custom provider with no mapping for the level fails the next request, naming the catalog file to add.

catalog_files

{ "catalog_files": ["~/.riffer/models.json", ".riffer/models.json"] }

The model catalog files riffer reads for per-model pricing and reasoning mappings. Without a catalog entry a model has no cost: it is shown as missing, never as zero. The file format is riffer’s.

mcp

The bundled mcp extension’s namespace, declaring the MCP servers whose tools the model gets. MCP has the format.

extensions

{ "extensions": { "disabled": ["mcp", "bash"], "autoload": true } }
  • disabled leaves out bundled extensions: any of read, write, edit, bash, agents_md, skills and mcp. Nothing a disabled extension would register exists.
  • autoload (default false) loads every installed gem that ships riffer/rig/extension (Gem extensions).

--no-extensions skips autoload and the rig.rb files for one run; the bundled extensions still load.

tools.native

{ "tools": { "native": { "web_search": true } } }

Switches on provider-native tools, per tool. They are off by default. A value can be an object instead of true, passed to the provider as the tool’s options: {"web_search": {"max_uses": 3}}. A switch the current provider does not support does nothing.

reload

{ "reload": "manual" }

"auto" (the default) reloads automatically when a rig.rb file or a file it requires changes; "manual" reloads only on /reload. Either way, /reload picks up settings changes. Reloading has the details.

Extension namespaces

Every top-level key that is not a core key belongs to the extension of that name, holding the keys it declares with rig.setting:

{
  "model": "anthropic/claude-sonnet-4-6",
  "git": { "depth": 10 }
}

A key left out takes the extension’s declared default. An extension cannot be named after a core key.
