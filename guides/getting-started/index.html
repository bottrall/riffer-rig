Install

riffer-rig needs Ruby 4.0 or later.

gem install riffer-rig

This installs the riffer executable.

First run

Run riffer from the project you want to work on:

cd my-project
riffer

With no model configured, it asks for one:

Which model should riffer use? Enter provider/name, with a provider from: amazon_bedrock, anthropic, azure_openai, gemini, openai, openrouter
› anthropic/claude-sonnet-4-6

The answer is saved as model in ~/.riffer/settings.json, so later runs skip the question. A model already set by --model, RIFFER_MODEL or either settings file is used without asking (Configuration).

The reasoning effort follows the same pattern: --reasoning, then RIFFER_REASONING, then reasoning in the settings, and /reasoning switches it inside the session (Configuration).

Next it looks for the provider’s credentials in the environment and in ~/.riffer/auth.json. When one is missing it asks for it, reading a key without echo:

anthropic api_key
› (hidden)

A pasted key is saved to ~/.riffer/auth.json (permissions 600) and reused from then on. Leaving the answer empty stops with a message naming the environment variable to set instead. Providers lists each provider’s variables and where to create a key.

The session

The banner shows the model, the working directory, how many skills were found and the version. On a terminal too narrow for the logo it leaves the logo out, and a model or working directory too long for its row is cut from the left behind …. It is drawn again when the session changes — /new, /resume — and for a session that has already used tokens it adds a session row with the total so far, and its cost once the model is priced. Type a prompt and press Enter:

  • while the turn runs, the status line under the input shows its turn number, time, tokens and cost, and Ctrl-T peeks at what the model is writing; between turns it shows the same slots as idle — the time, the tokens and cost used so far, the background jobs — at the same positions, so starting or ending a turn moves nothing;
  • when it ends, the reply is printed in one piece, and under it a stat line: the turn’s steps, time and tokens, then the session’s running total, each with its cost once the model is priced (Configuration);
  • you can keep typing while a turn runs: Enter queues the message, and it runs when the turn ends;
  • Ctrl-C cancels a running turn, which prints what the reply had reached and interrupted; with no turn running, a second Ctrl-C exits, as do /exit, /quit and Ctrl-D on an empty line.

/help lists the slash commands, Terminal has every key and what each command does, and the README lists the flags.

What first run leaves behind

In ~/.riffer/:

  • settings.json — the model you picked, and any other settings (Configuration);
  • auth.json — the credentials you pasted, permissions 600 (Providers);
  • sessions/ — one JSONL file per saved session (Sessions).

In the project, nothing: .riffer/ is only there if you add a project settings.json or rig.rb (Configuration, Extensions), and the first run of a project rig.rb asks you to trust it.
