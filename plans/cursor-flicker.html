Plan: fix cursor flicker during the spinner

The problem

While the "riffing…" equalizer is animating, the terminal cursor flips between a solid block and a hollow outline — occasionally, not constantly.

Why it happens

The animator redraws the spinner line many times a second using an erase-and-redraw sequence (\r … \e[K). Some terminals render the cursor as hollow for a frame when it sits mid-line on a freshly-erased row — the emulator's cursor draw races its own cell repaint. Nothing in rig emits cursor sequences today; the flicker is an artifact of that churn.

The fix — agreed decisions

Hide the cursor for the whole turn (your call, option 2), via a dedicated Riffer::Rig::UI::Cursor module (your call, option 1), wrapping only run_turn (your call, option 1 on scope).

  • New module lib/riffer/rig/ui/cursor.rb with hide and show methods.
  • It writes \e[?25l (hide) and \e[?25h (show) to the injected output.
  • Gated the same way as the animator and smoother: only when the theme is enabled and the output is a TTY. Piped runs stay escape-free.
  • REPL gains it as an injected collaborator (defaulted from the output/theme, like the animator and smoother are today).
  • Animator and smoother are left untouched.

Where it lives in the REPL

cursor.hide
│ animator.start
│ smoother.start
│ … stream events, renders, tool results …
│ animator.stop / smoother.finish
│ final newline
ensure → smoother.finish, animator.stop, cursor.show (show goes last, after all writes)
  • hide at the top of run_turn; show as the last statement of its ensure block — so the cursor comes back even on errors, and never before the smoother's final drain.
  • This covers skill-command turns too (run_skill_command delegates to run_turn).
  • The › prompt and the farewell message sit outside the turn, so the cursor is visible while you type.

Tests

  • test/riffer/rig/ui/cursor_test.rb: non-TTY output gets no escapes; TTY output gets hide on hide, show on show.
  • Extend the REPL test with a fake cursor collaborator: a turn hides once and shows once, including on the error path.

Verification

  • bin/ci (lint + tests + typecheck) passes before pushing.
  • bin/rbs run after the lib/ change, generated sigs committed.
  • You eyeball it live in your terminal: no more solid↔hollow flip while "riffing…" animates.

Tradeoff to accept

The cursor is invisible for the entire turn — the same behavior as gh, npm, and other polished CLIs while they're busy. It reappears the moment the turn ends (or errors out).
