Hosts

Three thin clients over the same Session: the terminal, the headless printer and the ACP adapter. Each implements the Host duck and renders the one event stream.

Scope

exe/riffer and the three host namespaces Riffer::Rig::Terminal, Riffer::Rig::Headless, Riffer::Rig::ACP, plus the standalone acp-sdk gem. The existing ui/ code (renderer, animator, banner, theme, palette, pixels, riffy) moves under Terminal. Files: exe/riffer, lib/riffer/rig/cli.rb (the dispatcher), lib/riffer/rig/terminal.rb and terminal/, lib/riffer/rig/headless.rb, lib/riffer/rig/acp.rb.

Depends on: every unit above; hosts use only the public Session, Host, Loader and Events API. Depended on by: nothing.

Decisions

The host tier and its discipline

  • exe/riffer is a small dispatcher: no arguments → Terminal; -p/--print → Headless; acp → ACP. acp is the only subcommand; there is no riffer sessions.
  • A host uses only the public Session, Host, Loader and Events API, enforced by a test that the Terminal, Headless and ACP namespaces reference no other Riffer::Rig constant. Anything a host needs becomes a Session or Loader feature, so embedders get it too.
  • Every CLI flag is a Session or Loader keyword first; the host only translates argv.
  • Hosts do nothing for reload; they get it through the Loader-built Session.

Terminal

  • The first host and the reference. The REPL, rendering of the event stream (streamed text, tool calls, reasoning, cost line from turn_end), input, and all the interactive prompts: model onboarding (list providers from the registry, ask for a model, write settings), credential recipes (ask with secret: true, the Bedrock chain-or-token choice), SDK install confirmation with a spinner under progress, project trust confirm, extension notify as an out-of-band line.
  • Implements all four Host methods and reports all four in capabilities.
  • Ctrl-C during a turn calls Session#cancel; a second Ctrl-C at the prompt exits.
  • Runtime commands come from session.commands and are dispatched with run_command; the terminal's own commands are only the lifecycle ones: /exit, /quit, /resume, /new. /help, if present, lists both sets from the same source.
  • /resume opens the project picker: type to search, Enter to switch, Ctrl-D then confirm to delete; rows show the first user prompt trimmed to one line, relative time and message count; --all escapes the cwd scope. /new starts a fresh session in place. Both replace the Session the host drives.
  • Everything under ui/ today (banner, animator, theme, pixels, riffy) stays as terminal presentation.

Headless

  • riffer -p "prompt" runs one prompt and exits. Stdin: when piped, its content is appended to the prompt argument as context; with no argument, stdin alone is the prompt; a TTY stdin is never read.
  • Loads exactly what the REPL loads through the Loader, minus whatever the strip flags remove. Never prompts: the null-host behaviour applies to onboarding, credentials, SDK install and trust.
  • Text output (default): only the assistant's text on stdout, streamed; reasoning not printed; errors and notify lines always on stderr. --verbose adds a one-line-per-tool-call trace to stderr.
  • --json: one JSON object per line for every Session event (riffer StreamEvents plus rig events), flat envelope {"type": "text_delta", ...to_h} with the type as the event class name in snake_case. The first line is session_start carrying the id. No final single-document format. A fatal configuration or runtime error is a last {"type": "error", ...} line.
  • -c, -r <id> and --no-save as in the shared table; riffer -p -c "now run the tests" is the multi-turn headless story.

ACP

  • Built second, after the terminal. It is the proof that Session is host-neutral and it is how non-Ruby developers get in. Same gem, riffer acp subcommand; editors register the agent as riffer acp.
  • Wire layer: a standalone MIT gem acp-sdk, namespace ACP, require "acp/sdk", repo bottrall/acp-sdk (created, empty apart from README and licence). Server and client sides, plain Ruby, JSON-RPC over NDJSON stdio, the official schema.json vendored and regenerated, no async dependency. It becomes riffer-rig's one non-riffer dependency; it must be published (claiming the gem name at first push) before riffer-rig can depend on it, and it has its own release train under the same policy.
  • Transport: stdio only. HTTP/WebSocket waits for the ACP RFD to stabilise and lands in acp-sdk, not riffer-rig.
  • The first server implements: initialize, session/new, session/prompt, session/cancel, session/update, session/request_permission (the six required, with permission requests answered "allow" since permissions are out of scope), plus client-supplied mcpServers on session/new (stdio shape only, through the rig.mcp seam), available_commands_update from session.commands, and session/load and session/list (added by the persistence decision; agentCapabilities advertises loadSession: true).
  • session/new returns the Session UUID as sessionId. session/load reads the entries through the Loader, restores the Session, replays user, assistant and tool entries as session/update chunks, then responds. session/list maps store.list(cwd:) to ACP's session-info shape (id, cwd, title = first prompt, updated_at).
  • The first server skips: fs and terminal delegation to the client, HTTP transport.
  • The adapter is the only place Session events are mapped to another vocabulary. Mid-turn multiplexing (a session/cancel arriving during session/prompt) is Session#cancel from the reader thread.
  • Implements notify as a session/update; ask, confirm, progress decline in the first server. Trust: a project rig.rb loads over ACP only once a terminal session has trusted it.
