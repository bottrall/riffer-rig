Bundled

The coding toolkit and the three shared conventions, each an ordinary extension the user can disable or replace.

Scope

Seven named extensions shipped in the gem: read, write, edit, bash, agents_md, skills, mcp. Each is built only on the registrar seams; nothing here reaches into the Session. Files: lib/riffer/rig/bundled.rb (the list and Riffer::Rig.bundled), lib/riffer/rig/bundled/<name>.rb (one file per extension), lib/riffer/rig/tools/{read,write,edit,bash}.rb (the tool classes, kept where they are).

Depends on: Extensions. Depended on by: Loader (loads them first), Hosts (the default bundle every shipped host gets).

Decisions

What is bundled and why

  • Step 3 of the core-versus-extension rule: the coding toolkit, plus any convention at least two of pi, OpenCode, Claude Code and Codex already share. Today that is AGENTS.md, Agent Skills and an MCP client. Anything else (hooks, git context, models.dev catalog, web search on a provider without it) is third-party.
  • Bundled items are the default because a shell and file access are the most efficient way to get almost any task done; the prompt still claims no coding identity. A host can pass a different set.
  • The Loader loads all seven before any rig.rb, so user extensions can replace them. The order is read, write, edit, bash, agents_md, skills, mcp.
  • Provider-native tools (web search, and later code execution or file search) are not bundled; they are core, off by default, and switched on in settings (Providers: provider-native tools).

read, write, edit, bash

The four tools keep their current behaviour, parameters and identifiers. Each is registered by its own bundled extension (Riffer::Rig.extension("read") { |rig| rig.tool Riffer::Rig::Tools::Read }) so it can be disabled or replaced one at a time. Each description gains one sentence of usage guidance, which is where the coding guidance from the old system prompt now lives:

ToolBehaviour keptGuidance sentence added to the description
readreturns a file with line numbers; offset/limit slice large files; missing file is a tool error"Read a file before editing it, and read rather than guess what a file contains."
writecreates or overwrites a file, making parent directories"Use this for new files or full rewrites; prefer edit for changes to an existing file."
editreplaces an exact string, unique by default, replace_all to replace every occurrence; ambiguous or missing match is a tool error"Prefer this over write for existing files; pass enough surrounding text to make old_string unique."
bashruns a command in the cwd in its own process group, combined stdout/stderr, exit status, per-call timeout, output truncated at 30,000 bytes"Use this for exploring and running things: ls, rg or grep, find, tests, git, package managers."
  • Tools never raise (riffer 0.43 contract); failures are tool errors the model sees.
  • bash reads the Session's cancel flag and kills its process group when set, instead of waiting for the message boundary.
  • Tools resolve relative paths against the Session's cwd, not Dir.pwd, so two Sessions in one process can work in different directories.
  • A tool's name on --tools and tools: is its riffer identifier: read, write, edit, bash, and whatever identifier an extension tool declares.

AGENTS.md (agents_md)

  • Registers one prompt section, :agents_md. Every turn it reads ~/.riffer/AGENTS.md and <cwd>/AGENTS.md (whichever exist) and renders them framed as user-authored instructions that outrank the base norms, one block per file with its path, in that order. The current implementation's <project_instructions path="…"> wrapping is the seed; the framing sentence is new.
  • Because the section is a Proc evaluated per turn, an edited AGENTS.md takes effect on the next request with no reload.
  • Relative paths mentioned inside an AGENTS.md are the model's business; the extension does not resolve them.
  • Off via "extensions": {"disabled": ["agents_md"]} or the strip keyword agents_md: false (--no-agents-md).

Agent Skills (skills)

  • Registers a Riffer::Skills::FilesystemBackend over ~/.riffer/skills and <cwd>/.skills through the skills seam, and one runtime command per discovered skill for activation. The command form today is /skill:<name> [args]; the reboot keeps it, and it is a runtime command so it works over ACP and headless too.
  • Activation reads the skill body through riffer's Skills::Context#read, sends it to the model as a user turn (ctx.prompt) wrapped as a skill, and emits skill_activated; the Loader's store records the name so a resumed Session re-activates by name.
  • The catalog the model sees is riffer's own second system message and is not touched. The :skills prompt section is reserved for anything rig adds about skills and is empty in v1, so a user can register their own :skills section without disabling the extension.
  • Off via "extensions": {"disabled": ["skills"]} or skills: false (--no-skills).

MCP client (mcp)

  • Registers, through the rig.mcp seam, every server declared under the core settings key "mcp": {"servers": {"<name>": {"command": "…", "args": […]}}}, home then project, project overriding by name. Stdio servers only; that is the shape the seam takes and the shape the ACP mcpServers parameter maps to.
  • Extensions declare servers of their own with the same seam; this extension is only the settings-driven convention.
  • Server tools appear to the model with riffer's MCP tool naming; they are not on the four-tool identifier list and are not filtered by --tools unless named.
  • On reload, a server whose name, command and args are unchanged keeps its connection; others restart. Session#close stops them all.
  • Off via "extensions": {"disabled": ["mcp"]}.

Disable and replace

  • Disable with "extensions": {"disabled": [...]} in either settings scope; the lists merge. A disabled bundled extension is simply not passed to Session.new.
  • Replace by registering under the same identifier from a later extension: a tool with identifier 'bash', a command named model, a prompt section :agents_md. Later wins; the override is logged at info level through notify. Nothing is deregistered, so the original is still reachable as Riffer::Rig.bundled(:bash).
  • The strip keywords (extensions: false, skills: false, agents_md: false, tools: [...]) are Loader concerns and are listed under Loader: interfaces. extensions: false strips rig.rb extensions only; the bundle stays.
